# Матрица приёмки персонализации

Все строки ниже — требования к будущей реализации. На момент подготовки пакета статус **planned**, не passed. Исполнитель переносит фактические статусы/команды в свой отчёт; эту таблицу не использовать как доказательство выполненных тестов.

После реализации 01–03 фактические проверки C/P/R доступны в [отчётах исполнения](../implementation/00-orchestration.md). Остальные блоки остаются planned. Ни количество unit-тестов, ни заполненная матрица не заменяют экспертную оценку значимости.

После этапа 04–05 фактические G/A и QA/history проверки опубликованы в [следующем отчёте](../implementation/04-05-orchestration.md). Это offline/fixture приёмка; live provider, независимая семантическая проверка и полнота требований 06–07 не объявляются пройденными.

Обозначения: C — контракт, P — профиль, R — ранкер, G — RAG, A — агент, B — бюджет, Q — QA, I — интеграция, E — оценка. Покрывать поведение тестами, а не просто наличие функции с подходящим названием.

| C07 | v2, затем v1, затем v3 withdrawn | Latest не откатывается и не воскресает из active v2 |
