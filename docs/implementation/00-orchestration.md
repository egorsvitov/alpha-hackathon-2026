- Из них 6 оркестраторских интеграционных тестов: одно событие/три профиля, точное совпадение CLI fixture-import и Python API, ingest→rank через одну БД и receipt cutoff, отзыв без возврата к active-версии, запрет fixture-import/часов в live; реальный attach_payment_graph → provenance → entity resolver → ranking с clean/limited качеством. В последнем тесте одинаковая наблюдаемая доля 0.8 даёт 48 базовых баллов при clean_observed и только 5 при потерях от дублей.
- `uv run --frozen python -m ranking demo --as-of 2026-10-20T18:00:00+03:00 --output-dir data/processed/personalization/orchestration-demo` — успешно, три результата находятся локально в ignored-каталоге.

## Локальные реальные данные

Прогон владельца профилей: 85 525 строк / 85 514 company IDs, один конфликтующий ID с 12 строками; нормализованы все 85 513 неконфликтных профилей. Полная schema-проверка выполнена для трёх выбранных профилей до/после графа; это не заявление о schema-прогоне каждого профиля всей базы.

Платёжный файл: 1 380 585 строк, для трёх выбранных компаний отобрано 1 278. Прогон нормализации занял 22.744 с, графа — 1.669 с; пиковый RSS процесса 257 044 KiB. Это разовый локальный замер, не нагрузочный SLA. Hash исходных CSV до/после совпал. Реальные профили и агрегаты не копировались в Git fixtures, сохранены только под `data/processed/personalization/`.

## Готовый маршрут и ограничения

Теперь работает: **B6 → валидация/версии → профиль → сигналы → оценка → персональная лента с причинами**. Запуск и трактовка результата описаны в [ranking/README.md](../../ranking/README.md). DEMO_LOGISTICS, DEMO_IT и DEMO_TRADE имеют разные применимые каналы. При отсутствии достаточных баллов лента может быть пустой; это не скрывается под искусственно поднятым score.

Это эвристический baseline. Независимой экспертной разметки и измерения качества рекомендаций пока нет. Нет embedding retrieval/обученного ранкера, автоматического entity resolution и индекса для большого потока. Доступные события перебираются для одной запрошенной компании, общей матрицы 85 тысяч компаний × все новости нет. Сильные платёжные доли используются только при пригодном качестве очищенного поднабора и всё равно не объявляются доказанной бизнес-зависимостью.

Producer Article→EventBundle, банковский RAG, LLM-интерпретация, общий бюджет live-моделей и UI-интеграция относятся к следующим блокам. Задания 04–07 остаются планом; успешный offline ranking не доказывает их готовность.
