# 05C: QA, immutable history, follow-up questions

Задание: `docs/agent-tasks/05-analyst.md`, совместимые ports владельца 05A. Исходный commit: `2453da0`.

Реализованы `llm/agent/qa.py`, `run_store.py`, `questions.py`; targeted tests в `test_qa.py`, `test_run_store.py`, `test_questions.py`, полностью synthetic сохранённый context/draft в `tests/fixtures/qa_history/forecast.json`.

RunStore принимает explicit SQLite path, сохраняет полный pinned RunContext, append-only content-addressed JSON artifacts, step records и единственный final result. Finished run sealed: новые artifact/step/result запрещены; вопрос создаёт child, parent остаётся побайтно тем же по public read API. Run IDs исключительно SQL values, не filesystem paths. Strict JSON serialization запрещает nonfinite values и нестроковые object keys; decoder запрещает duplicate keys/nonfinite. Context/artifact hash проверяются при чтении. Restart, orphan parent rejection, duplicate run, corruption и `../../outside` ID проверены.

QA возвращает единственный `ports.QAReport` с status/next_action/issues/checks/missing_evidence_queries и раздельными structural/semantic/publication status. Structural pass даёт limited; independent semantic review всегда not_run. Critical errors блокируют publication, включая чужие refs/company/profile, exact source text/modality/polarity drift, registry/quote substitution, неподдержанные связанные числа, числовой вывод на unresolved conflict, ложную атрибуцию позиции банка, любой bank_view без отдельной смысловой проверки, безусловный финансовый эффект при неизвестных договорных условиях, excluded sources и malformed typed draft. Requested evidence передаётся оркестратору как retrieve_more. Empty available sections отвергаются. Это узкие guards, а не универсальная семантическая проверка; heuristics имеют ложноположительные и непокрытые случаи.

answer_question проверяет company/role binding перед доступом к ответу, загружает последний сохранённый context artifact, создаёт child run. Новые сведения вопроса сохраняются только как unverified user-supplied assumptions, profile не меняется. Текущее событие проверяется через event_store/clock: withdrawn или новый snapshot останавливают ответ; explicit historical_replay помечен в результате. Без current store обычный ответ fail-closed. При отсутствии bank evidence выполняется максимум один дополнительный реальный retrieval, did_extra_search=true только на границе вызова; as_of и RAG policies берутся из pinned context. Evidence проходит общий schema/identity/corpus verification, новый context — общий bounding builder. Полный размер с вопросом проверяется до generation. Generation/QA переиспользуют общие порты; до 06A доступен только explicit fixture mode. На failure сохраняются partial evidence/draft/QA/error artifacts и stopped result.

HTTP/backend авторизация и UI не проверялись. Identity binding здесь дополняет backend auth, не заменяет его. Fixture отвечает по явным шаблонам и не доказывает качество reasoning. Полный runtime workflow framework не добавлялся.
