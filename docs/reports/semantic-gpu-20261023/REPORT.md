# GPU-эксперимент: смысловые группы новостей

23 октября 2026. Версия для Git без текстов новостей.

[Открыть интерактивную карту](index.html). HTML открывается локально, без сервера и сети.

## Итог

Обработаны 1000 заранее выбранных статей, затем весь снимок: **3621 статья, 5128 фрагментов, 5035 уникальных векторов, 26 источников**.

Начальная экспериментальная рекомендация — semantic, threshold=0.65. Временной вариант alpha=0.4 / half-life=7 выбран по dev с правилом ничьих, но на малом test потерял полезные связи. Его лучше проверять как отдельный режим хронологии. Production-качество не доказано.

Модель BAAI/bge-m3, ревизия `5617a9f61b028005a4858fdac845db406aefb181`, 1024D dense, FP32 CUDA, L2-normalized. Порог не является вероятностью; группы предназначены для совместного чтения, не подтверждают идентичность события.

## Смысл и время

| Semantic | 1563 | 719 |

На dev 16 полезных / 4 отрицательных / 2 неопределённых пары; threshold 0.65 сохранил 7/16 полезных, 0/4 отрицательных. Пороги 0.75 и 0.85 сохранили 3/16 и 2/16. Проверены девять временных комбинаций; пять дали 7/16, выбран режим 0.4/7 правилом ничьих. Test при настройке не использован.

На test: 10 полезных, 5 отрицательных, 1 неопределённая пара. В выборке semantic сохранил 5/10, time 2/10; на полном корпусе 4/10 и 1/10. Оба объединили 0/5 отрицательных. Такой малый набор не доказывает precision всего корпуса. Неразмеченные пары неизвестны, не отрицательные.

Временной вариант потерял 80 849 внутригрупповых пар и добавил 1 647: изменение порядка complete-link не гарантирует вложенность. Близкий сосед может остаться в другой группе из-за худшей пары со всей группой. Publication time не подменяет event time.

## Качество и API

Оценены 22 dev-пары + 16 test-пар + 24 диагностических случая групп. Для 24 групп: 18 полезны для совместного чтения, 2 пропущенные связи, 4 неопределённых. Самая большая группа проверена лишь в 6 из 217 фрагментов. Все оценки — single_annotator_draft от Codex, без независимого человеческого арбитража.

API: 69 попыток, 67 HTTP 200, 2 транспортные/локальные ошибки, 59 формально валидных результатов, 8 finish_reason=length; 5 крупных групп не отправлены. 424134 токена: 315103 input + 109031 output. Сумма usage.cost = 12.873778452030210067; **валюта не подтверждена, это не сумма в рублях**.

После default-профиля проверен thinking-disabled, затем компактный формат дал 51 валидный ответ на других группах. Это непарный опыт, не доказательство причинного улучшения. Запросы не повторялись скрыто; один общий журнал с атомарным cap=200. Пять больших контекстов пропущены целиком, не усечены.

Шесть обобщений прочитаны отдельно: одно поддержано, одно с оговорками, три частично, одно с неподтверждёнными цитатами. Существование ссылок не доказывает смысловую поддержку. Диагностический отбор не даёт популяционную оценку качества.

## Карта и воспроизводимость

PCA50 randomized → t-SNE, perplexity=40, max_iter=1200, init=pca, learning_rate=auto, seed=20261023; 4 CPU-потока. PCA-вид использует первые две компоненты того же fit. Координаты не зависят от группировки.

Trustworthiness@10 к исходному 1024D cosine: t-SNE 0.9732, PCA 0.7873. Recall десятки соседей: 50.73% и 11.74%. PCA2 объясняет 15.25% дисперсии. Все 5128 точек оценены, self исключён; копии оставлены, равные ранги разрешаются стабильным порядком.

[Методика t-SNE](https://scikit-learn.org/stable/modules/generated/sklearn.manifold.TSNE.html), [trustworthiness](https://scikit-learn.org/stable/modules/generated/sklearn.manifold.trustworthiness.html). Острова, плотность и 2D-расстояния не являются вероятностями и не заменяют исходные scores.

Версия для Git сохраняет координаты, IDs, даты/источники, membership, округлённые до 6 знаков scores соседей, метрики и обезличенные диагностические заметки. Заголовки, тексты, URL новостей, prompts, финальные API-ответы, ключи и базы отсутствуют. Проверка цитат по тексту доступна только в полной локальной версии.

Сборка: `scripts/semantic_gpu/publish_report.py`. Публичные заметки: `scripts/semantic_gpu/report/public_notes.json`. Для пересборки из приватных артефактов нужен локальный HTML, а не доступ к API. `projection.json`, `manifest.json`, `issues.json` фиксируют координаты, хэши и диагностику.

## Ошибки, гипотезы и предложения

### Q01 · P0 · Ссылка существует, но не подтверждает утверждение

Статус: Открыто.

Наблюдение: В одном из шести проверенных обобщений несколько утверждений ссылаются на фрагменты, не содержащие нужных фактов. Сами сведения могут быть в другом месте полного документа. Проверка IDs прошла.

Гипотеза: Полный документ даёт модели факты вне выбранных units; проверка валидирует ID, а не смысл ссылки.

Предложение: Разделить цитируемые фрагменты и контекст; для каждого атомарного утверждения сохранять подтверждающий span. При нехватке доказательств не выпускать утверждение. Не считать references_exist оценкой достоверности.

Как проверить: На отложенных длинных статьях независимо разметить claim→span; сравнить долю неподтверждённых утверждений и полноту покрытия до/после, включая контекст вне группы.

### Q02 · P1 · Составное утверждение прикрыто неполными ссылками

Статус: Открыто.

Наблюдение: В двух проверенных обзорах составное утверждение или датированное изменение опирается лишь на часть необходимых фрагментов. Существование цитат не подтверждает все части предложения.

Гипотеза: Модель объединяет несколько фактов в предложение и экономит ссылки. Проверка наличия ID не проверяет все части предложения.

Предложение: Один проверяемый факт на item; проверять покрытие каждой сущности, даты и числа достаточными ссылками. Показывать неприведённые фрагменты отдельно.

Как проверить: Сравнить атомарный и текущий формат на многообъектных группах; оценивать полноту доказательств по утверждениям, а не только количество ссылок.

### Q03 · P1 · Разные метрики и обновления названы противоречиями

Статус: Открыто.

Наблюдение: В проверенных обзорах значения разных финансовых инструментов и последовательные обновления расписания ошибочно названы противоречиями.

Гипотеза: Сравнение по близкой теме и различающимся числам не учитывает инструмент, базис, период и версию сообщения.

Предложение: Ввести ключ сравнимости: объект, метрика, инструмент, период наблюдения, единица, версия и источник. Отдельные типы: расхождение, обновление, разные показатели; contradiction только для несовместимых утверждений при одинаковых условиях.

Как проверить: Собрать контрастные пары spot/futures, прогноз/факт, новая/старая версия и несовместимые показания; измерить ложные contradiction отдельно.

### Q04 · P1 · Публикация подменяет время события

Статус: Открыто.

Наблюдение: Часы из UTC-метаданных показаны без зоны; публикация подменяет датировку события. Исторические эпизоды внутри одной статьи получают одинаковую дату публикации.

Гипотеза: Доступная дата публикации используется как универсальная дата всех упомянутых событий.

Предложение: Хранить publication_time и event_time раздельно, с точностью, зоной и происхождением. Не достраивать event_time без опоры на текст. Указывать зону и различать планы, сообщения и состоявшиеся события.

Как проверить: Разметить даты на материалах с ретроспективой, относительными датами, репостами и day precision; проверять неверные временные утверждения и хронологический порядок.

### G01 · P1 · Временной штраф разрывает полезные пояснения

Статус: Открыто.

Наблюдение: В диагностическом случае разновременное пояснение разделено с исходным сообщением. На малом test полезные пары падают с 5/10 до 2/10 в выборке, с 4/10 до 1/10 на полном корпусе.

Гипотеза: Период между публикациями слабо связан с полезностью совместного чтения; поздняя статья часто объясняет раннюю.

Предложение: Оставить semantic базовым режимом. Проверить время как сортировку/фильтр и отдельные связи «уточнение», а не обязательный штраф каждой паре; отдельно извлекать даты события.

Как проверить: Отложить разновременные сюжеты и оценить сохранение поясняющих связей и примеси старых похожих событий. Сравнить без времени, штраф и хронологическое ранжирование.

### G02 · P1 · Временные группы не являются простым разбиением смысловых

Статус: Свойство алгоритма.

Наблюдение: В полном корпусе исчезают 80 849 внутригрупповых пар и появляются 1 647 новых. В одном проверенном случае два фрагмента остаются вместе, но к ним добавляется третий.

Гипотеза: Изменение попарных расстояний меняет порядок complete-link слияний. Даже меньшие scores не гарантируют вложенность финальных разбиений.

Предложение: Показывать оба направления переходов и маркировать snapshot/config в group_id. Если продукт требует вложенности, явно разбивать каждую исходную группу независимо и оценить потери такого ограничения.

Как проверить: Проверять lost/gained pairs и сохранение покрытия на каждом снимке. Для вложенного варианта проверить отсутствие новых межгрупповых пар и сравнить качество.

### G03 · P1 · Близкий сосед может остаться в другой группе

Статус: Свойство алгоритма.

Наблюдение: Два одиночных фрагмента имеют сильные связи с соседями из других групп, но не присоединяются к ним. Complete-link учитывает худшую пару со всей группой.

Гипотеза: Задача полезных связей шире взаимоисключающего разбиения на полные клики при пороге.

Предложение: Показывать related-связи между группами и точные соседства независимо от членства. Проверить многоуровневое представление; не заменять вслепую single-link из-за риска цепочек.

Как проверить: Разметить мосты, синглтоны и транзитивные цепочки; сравнить recall полезных связей и загрязнение крупных групп.

### G04 · P1 · Шаблоны создают гигантский операционный каталог

Статус: Открыто.

Наблюдение: Крупнейшая смысловая группа содержит 217 шаблонных биржевых фрагментов с разными объектами и датами. Прочитаны только 6; оценка всех 217 не выставлялась.

Гипотеза: Общий шаблон риск-параметров доминирует над редкими сущностями и числовыми условиями.

Предложение: Помечать тип источника и шаблон; проверить удаление boilerplate с картой offsets, извлечение тикеров/метрик и иерархию каталога. Вводить читательский бюджет с явным покрытием вместо молчаливого отсечения.

Как проверить: Сравнить body-only, текущий текст и очищенный текст на заранее зафиксированном наборе шаблонных/обычных статей; оценить смешение инструментов, recall и размер групп.

### G05 · P1 · Навигация и подвалы становятся содержательными фрагментами

Статус: Открыто.

Наблюдение: Навигационные каталоги без новых чисел и служебные подвалы попадают в содержательные группы. Сходство шаблонов не добавляет сведений к новости.

Гипотеза: Фрагментация извлечённого текста сохраняет служебные элементы; тематические ссылки похожи на содержимое статьи.

Предложение: Определять navigation/footer и provenance качества извлечения; сохранять исходник, а очищенную версию и offsets версионировать. Не выдавать числа, которых нет в тексте.

Как проверить: Вручную разметить извлечение на разных источниках; измерить долю мусорных units и потерю настоящих фактов после очистки.

### G06 · P2 · Репосты создают видимость независимого подтверждения

Статус: Открыто.

Наблюдение: В проверенном случае два источника пересказывают одно первичное сообщение. В корпусе 38 семейств точных копий и 77 документов сверх одного на семью.

Гипотеза: Число доменов не равно числу независимых наблюдений; семантические копии не исчерпываются точными хэшами.

Предложение: Сохранять цепочку атрибуции и семейство репоста, показывать количество документов и независимых первичных сообщений отдельно.

Как проверить: Разметить происхождение и перифразированные копии; проверить устойчивость групп и split без утечки семей между dev/test.

### G07 · P2 · Одна статья содержит разные компании, годы и события

Статус: Открыто.

Наблюдение: Длинные статьи содержат разные компании, периоды и исторические эпизоды. Все части получают одну дату публикации; временной штраф внутри документа их не различает.

Гипотеза: Общее заглавие и контекст документа усиливают тематическую близость, а publication_time одинаков для всех частей.

Предложение: Проверить сущностно-событийную сегментацию и влияние заголовка отдельной абляцией. Сохранить связь «из одной статьи», не выдавая её за идентичность события.

Как проверить: Разметить многосюжетные документы и проверить смешение субъектов/периодов при одинаковом publication_time; оценить потери контекста после сегментации.

### A01 · P1 · Лимит вывода исчерпан до готового JSON

Статус: Обход проверен.

Наблюдение: 8 ответов default-профиля завершены finish_reason=length при max_tokens=4096. В отдельных случаях весь бюджет ушёл на reasoning без готового обобщения. HTTP 200 не означает успешный результат.

Гипотеза: Общий лимит делится между reasoning и финальным выводом, а длинные ID и многословный формат усугубляют расход.

Предложение: Проверенный обход: отключение thinking и компактный формат дали 1 + 51 корректный ответ на других группах. Проверять finish_reason, JSON и ссылки. Короткие локальные ID и планирование токенов — следующие эксперименты.

Как проверить: Сравнить профили на одинаковой зафиксированной выборке, включая качество цитат, токены и latency. Текущие непарные 52 успеха не доказывают причинное улучшение качества.

### A02 · P1 · Пять групп не отправлены из-за большого контекста

Статус: Явный пропуск.

Наблюдение: 5 уникальных групп превышают лимит полного контекста 100 000 bytes. Они отмечены unprocessed; фрагменты не обрезались молча.

Гипотеза: Полные документы дублируются в группе, а размер крупных шаблонных кластеров превышает бюджет.

Предложение: Оценивать bytes и токены до вызова; исследовать иерархическое обобщение с полным журналом покрытия и происхождением каждого claim. Не считать пропуск готовым обзором.

Как проверить: Прогнать крупнейшие группы с пакетированием; проверить покрытие всех units, объединение повторов и отсутствие новых фактов на reduce-этапе.

### A03 · P1 · Невалидный ключ и таймаут подключения

Статус: Исправлено в окружении.

Наблюдение: Первая попытка остановилась до HTTP из-за не-ASCII ключа, последующая дала provider_timeout. Обе сохранены; после исправления и явного резервного endpoint ответы получены.

Гипотеза: Ошибка локальной конфигурации ключа и отдельная проблема доступности транспорта; это не ошибка группировки.

Предложение: Проверять наличие и ASCII ключа до резервирования вызова; явно фиксировать endpoint и профиль без секрета. Сохранить конечные таймауты, учёт неопределённого расхода и явное разрешение повторов.

Как проверить: Моками проверить невалидный ключ, connect/read timeout и восстановление журнала; не повторять живые платные вызовы ради UI.

### A04 · P2 · Стоимость не имеет подтверждённой валюты

Статус: Ограничение учёта.

Наблюдение: usage.cost суммарно 12.873778452030210067, валюта не определена. 424 134 токена, 69 попыток, 67 HTTP 200 и 59 формально валидных результатов. Локальный cap 200 вызовов не равен остатку общего дневного бюджета.

Гипотеза: Provider cost является собственной единицей шлюза; точная тарификация и расход других участников неизвестны.

Предложение: Сохранять исходный usage и cost_rub=null; получить официальную валюту/тариф или баланс шлюза до пересчёта. Учитывать неопределённую цену транспортных ошибок.

Как проверить: Сверить журнал с официальным биллингом; проверить атомарный счётчик при параллельных вызовах. Не маркировать cost знаком ₽ без подтверждения.

### I01 · P2 · Загрузка весов: таймауты Xet и HTTP

Статус: Восстановлено.

Наблюдение: Xet остановлен после 406.85 с; прямой HTTP также был нестабилен. Диапазонная загрузка через реплику совпала с официальным LFS SHA-256 закреплённой ревизии. Восстановление заняло около 21 мин 24 с.

Гипотеза: Сетевой транспорт был нестабилен; замер включает неудачные попытки и не является чистым benchmark HF.

Предложение: Переиспользовать проверенные диапазоны, ограничивать параллелизм и таймауты, принимать файл только после проверки точного размера и SHA-256. Сетевую фазу отделять от загрузки модели в GPU.

Как проверить: Проверять повреждённую/неполную часть и hash mismatch на тестовых файлах; воспроизвести offline-запуск из готового кэша.

### I02 · P2 · Квадратичные матрицы остаются на CPU

Статус: Ограничение метода.

Наблюдение: Для 5128 фрагментов два сравнения занимают 11.65 и 10.99 с, общий wall 26.70 с, peak RSS 1.23 GiB. Рабочие матрицы оценены как 40×N². GPU ускоряет эмбеддинги, complete-link остаётся на CPU.

Гипотеза: При дальнейшем росте корпуса O(N²) память и pairwise-работа станут основным ограничением.

Предложение: Сохранять явные лимиты и оценку ресурсов до расчёта. Исследовать ANN-кандидаты или иерархические партии с отдельной проверкой эквивалентности/recall; не обещать неизменные группы после смены алгоритма.

Как проверить: Масштабный benchmark по N: wall/RSS/neighbor recall и изменения членства относительно точного метода на допустимом подмножестве.

### E01 · P1 · Малая, тематически узкая и не независимая разметка

Статус: Ограничение доказательств.

Наблюдение: 22 dev-пары, 16 test-пар и 24 случая групп — черновик Codex по исходникам. Dev тематически концентрирован, test мал. Шесть обзоров проверены диагностически; независимого человеческого арбитража нет.

Гипотеза: Текущая оценка может переоценивать переносимость на другие источники, темы и похожие разные события.

Предложение: Зафиксировать разнообразный story-disjoint holdout, несколько аннотаторов и арбитраж; отдельно оценивать relatedness и same-event, сложные отрицательные пары и перифразированные репосты.

Как проверить: Согласие аннотаторов и доверительные интервалы по сюжетным семьям. Не считать неразмеченные пары отрицательными и не выдавать 59 валидных JSON за 59 качественных обзоров.

### E02 · P2 · Выбранное время не доказало улучшения

Статус: Ограничение выбора.

Наблюдение: Порог 0.65 выбран на dev; пять временных конфигураций сохранили 7/16 полезных пар. Alpha 0.4 / half-life 7 выбран правилом разрешения ничьих. Число групп не является качеством.

Гипотеза: Малый dev недостаточно различает временные режимы; высокая чувствительность к сюжетному составу.

Предложение: Сохранить dev-only выбор и параметры, не перенастраивать по test. Проверить устойчивость на новых семействах, разнести настройку и финальный аудит.

Как проверить: Новый независимый holdout плюс анализ чувствительности порога, half-life и доли источников; отчёт о числе наблюдений для каждой метрики.

### V01 · P2 · Двумерная карта искажает 1024-мерную геометрию

Статус: Измеряется в отчёте.

Наблюдение: Обе проекции искажают исходную геометрию. t-SNE сохраняет 50.73% десятки cosine-соседей, PCA — 11.74%; trustworthiness@10 — 0.9732 и 0.7873. Копии сохранены, при равенстве используются стабильные ранги.

Гипотеза: Острова t-SNE могут выглядеть убедительнее реального качества групп, а глобальные расстояния между островами не несут нужного смысла.

Предложение: Показывать две проекции, trustworthiness@10 и recall@10 к исходному cosine; фиксировать seed и IDs. Рядом с точкой выводить сохранённые настоящие scores и членство независимо от проекции.

Как проверить: Проверить соответствие всех 5128 ID координатам и группам; сравнить локальные соседства на всём снимке, не подбирать проекцию по красивому виду.

### E03 · P2 · Кэш, wall и VRAM нельзя смешивать в одну скорость

Статус: Ограничение замера.

Наблюдение: 23.46 уникальных текста/с включают батчи, нормализацию и запись кэша, без скачивания и model load. nvidia-smi опрашивался раз в секунду; короткие пики могут быть пропущены. Пробы batch16/32 были на разных текстах; OOM не было.

Гипотеза: Неверное объединение фаз создаёт завышенные ожидания по скорости и заниженные оценки памяти.

Предложение: Отдельно показывать сеть, модель load, inference/cache, CPU grouping, API. Различать allocator allocated/reserved и sampled device. Для batch benchmark зафиксировать одинаковые тексты и прогрев.

Как проверить: Повторить профилирование одинаковых батчей в контролируемом окружении; сохранять временные ряды и конфигурацию. RAM и VRAM не суммировать.
