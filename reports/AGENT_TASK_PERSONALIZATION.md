## Контекст проекта и твоя роль

Мы участвуем в хакатоне Альфа-Банка. Нужно сделать сервис, который отбирает внешние новости для конкретной компании и объясняет их возможное влияние, используя признаки компании, ее наблюдаемые связи и аналитику банка.

Команда: два backend-разработчика, два ML-инженера, аналитик. Наша зона — **ML 1: профили компаний и персонализация ленты**. Другие участники будут делать парсер, RAG, LLM-интерпретацию, API и UI. Готового приложения пока нет. В папке уже есть исследовательские скрипты, отчеты, OCR и черновики контрактов; изучи и используй подходящее, сохрани их работоспособность.

Цель первого этапа: **один набор событий дает разные обоснованные рейтинги для разных компаний из CSV**. Реализуй подготовку профилей, объяснимый baseline, небольшой демонстрационный набор и оценку. Это cold-start content-based recommendation: истории кликов и готовых целевых меток нет.

## Шаг 1. Подготовить нормализованный профиль

Сделай переиспользуемую Python-функцию получения профиля по `SYNTHETIC_U`.

Предусмотри:
- ID, ОКВЭД как строку с сохранением точек, исходное название деятельности;
- укрупненную отрасль на основе явно описанных правил по ОКВЭД; неизвестные коды не угадывать;
- исходное числовое значение выручки и статус единицы измерения;
- регион, город, стадии/категории возраста и численности;
- продуктовые флаги `true/false/null`;
- `missing_fields`, `data_quality_warnings`, версию профиля;
- происхождение признаков: файл, исходное поле, ID записи; хэш исходного файла на уровне метаданных набора.

Выбери воспроизводимо три компании из CSV с различающимися отраслями и/или продуктами. Желательно крупные: при допущении единицы «рубли» это `REVENUE_COMPANY > 15e9`; такое допущение явно отрази в отчете. Предпочитай `CL_TYPE=CLIENT`. Не меняй исходные признаки ради красивого примера. Объясни выбор. Не загруженный граф отмечай `not_loaded`, а не «контрагентов нет».

## Шаг 2. Подготовить вход событий

Создай 12–15 явно синтетических событий: ставка, топливо, труд/зарплаты, потребительский спрос, валютная/внешнеторговая тема, отраслевые и региональные события, а также неполное событие и событие с неподдерживаемой темой.

Зафиксируй минимальный формат `NewsEvent`:
- `event_id`, `title`, `text`, `published_at`, `synthetic=true`;
- темы/теги, при необходимости затронутые отрасли, регионы и продуктовые чувствительности;
- неизвестные значения и качество данных.

Темы в этих примерах размечены вручную. В первом этапе не требуется извлекать их из произвольного текста, парсить интернет или вызывать LLM. Не выдавай эти тесты за реализацию классификатора или системы приема новых сырых новостей. В README четко укажи, какой подготовленный вход ожидается от будущего upstream-компонента.

## Шаг 3. Сделать объяснимый baseline ранжирования

Реализуй функции вида:

```python
build_company_profile(company_id) -> CompanyProfile
score_event(profile, event, as_of) -> EventScore
rank_events(profile, events, as_of) -> list[EventScore]
```

Используй простые правила соответствия отрасли, продуктовых признаков, географии и свежести. Правила и веса вынеси в небольшую версионируемую конфигурацию. Формулу и допустимый диапазон score объясни. Score — условная релевантность, не вероятность убытка и не денежный эффект.

Результат по событию: `event_id`, `score`, `reasons`, `features_used`, `missing_context`, `scoring_version`. Каждая причина должна ссылаться на фактический признак профиля и признак события. Недостаток информации отражай отдельно от низкого балла. Отсутствие совпавшего правила не доказывает нерелевантность.

Передавай `as_of` явно, чтобы демонстрация была воспроизводимой. Будущие относительно него события не должны попадать в текущую ленту. Определи поведение для неизвестной даты и равных баллов. На этом этапе допустима простая детерминированная эвристика, без обучения и эмбеддингов.

## Шаг 4. Подготовить первичную оценку

Для пар «три компании × события» создай черновую ручную разметку значимости 0–3 с объяснением. Неизвестную значимость отделяй от нулевой.

Критерии: 0 — по доступному контексту существенная связь не выявлена; 1 — возможная косвенная связь; 2 — понятный механизм потенциального влияния; 3 — обоснованный высокий приоритет. Не обещай конкретные финансовые последствия без данных.

Разметка, созданная тобой, имеет статус `provisional_not_expert_reviewed`. Ее должен проверить аналитик команды. Не порождай labels формулой собственного скоринга и не называй совпадение с ними объективным качеством. Рассчитай nDCG@5 и Precision@5 с документированным порогом релевантности. Укажи размер набора и ограничения; корректно обработай компании без релевантных событий.

## Шаг 5. Показать результат и проверить поведение

Сделай CLI, который одной командой строит три профиля, ранжирует один и тот же набор событий и сохраняет JSON плюс читаемую таблицу/Markdown: компания → top-5 → балл → причины. Читатель должен видеть, какие реальные различия профилей изменили порядок. Если различия малы, честно объясни, какие признаки и правила отсутствуют; не подгоняй исходные данные.

Нужны небольшие проверки важных свойств: конфликтный ID, unknown-флаг, неизвестный ОКВЭД, пустой набор событий, событие из будущего, воспроизводимость порядка. Добавь несколько содержательных контрпримеров, где отраслевое или продуктовое соответствие обоснованно меняет приоритет. Не заполняй проект тестами, которые просто повторяют веса формулы.
