# News pipeline — сбор внешних новостей (пункт 2)

Универсальный парсер, который собирает поток внешних новостей в единый
промежуточный формат для NLP-модуля (пункт 1). Выход — JSONL-накопитель,
где каждая строка — одна статья в формате команды.

## Зачем это

Пункт 1 (агент) превращает статьи в `EventBundle` по
`docs/contracts/event-bundle.schema.json` и строит персонализированный вывод.
Наша задача — дать ему чистый, предсказуемый поток сырых статей без LLM:
дёшево, быстро и легко проверять. LLM к парсеру не подключается.

## Формат записи (согласован с командой)

```json
{
  "article_id": "cbr_rss:3f2a9c1d0e4b",
  "source": "cbr_rss",
  "url": "https://www.cbr.ru/...",
  "title": "Заголовок",
  "published_at": "2026-10-20T12:00:00+03:00",
  "language": "ru",
  "text": "Текст для обработки NLP-модулем..."
}
```

- `article_id` — стабильный: `source:<sha1(url)[:12]>`. Повторный проход по той же
  ссылке даёт тот же ID, это основа дедупликации.
- `published_at` — ISO-8601 или `null`. Дата не выдумывается.
- `text` — может быть пустым, если текст не извлёкся (статья всё равно сохраняется).

## Запуск

```bash
# установка зависимостей (Python 3.10+)
python3 -m venv .venv_news
.venv_news/bin/pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org -r news/requirements.txt

# все источники
.venv_news/bin/python news/collect.py

# только макро/официальные источники
.venv_news/bin/python news/collect.py --category macro official

# без полного текста (быстрая проверка объёма)
.venv_news/bin/python news/collect.py --headlines-only

# smoke-тест без сети
.venv_news/bin/python news/smoke_test.py
```

Результат — `data/processed/news/news_corpus.jsonl` (накопитель, переживает
перезапуски). Скачанные страницы кэшируются в `data/processed/news_cache/`.

## Крупная выгрузка (~10k статей) для кластеризации

Для подготовки большого корпуса с полным текстом (под последующую
кластеризацию сокомандником) используйте `news/dump_large.py`:

```bash
# цель 10 000 статей из всех источников реестра
.venv_news/bin/python news/dump_large.py --target 10000

# ограничить время (напр. 30 минут) и категории
.venv_news/bin/python news/dump_large.py --max-seconds 1800 --category business macro

# лимит записей с одного источника
.venv_news/bin/python news/dump_large.py --limit-per-source 150
```

Особенности: собирает полный текст, пропускает заблокированные источники,
пишет накопитель после каждого источника (не теряет при сбое), продолжает
с места остановки (дедуп по URL). Корпус — `data/processed/news_bulk/news_corpus.jsonl`.

> ⚠️ На корпоративной сети большая часть HTTPS-источников блокируется MITM
> прокси (SSL-ошибки). Полноценную выгрузку 10k статей запускайте вне
> корпоративного Wi-Fi (дома/хотспот) — там доступно большинство источников.

Замечание: на корпоративной сети PyPI закрыт SSL-проверкой, поэтому в примерах
используются `--trusted-host`. Версии зависимостей зафиксированы в
`news/requirements.lock`.

## Структура

```text
news/
  collect.py           # CLI-точка входа
  smoke_test.py        # офлайн-проверка пайплайна
  requirements.txt     # зависимости
  requirements.lock    # зафиксированные версии
  sources.json         # реестр источников (единственное место их настройки)
  core/
    model.py           # Article / ArticleCandidate (контракт входа)
    registry.py        # SourceSpec + реестр
    fetcher.py         # HTTP: ленты, текст, кэш (единственный сетевой слой)
    identity.py        # стабильные ID + нормализация времени
    store.py           # JSONL-накопитель (атомарная запись)
    pipeline.py        # оркестратор прохода
  profile/             # профилирование целевой аудитории → тематика батчей
    audience.py        # анализ CSV (юрлица/платежи) → AudienceProfile
    batch_plan.py      # профиль → план батча (темы/регионы/страны/источники)
    topic_filter.py    # фильтр кандидатов по плану (без LLM, на этапе сбора)
    plan_cli.py        # CLI: показать профиль и план батча
    source_discovery.py    # поиск новых источников под темы аудитории
    source_discovery_cli.py # CLI: показать/проверить/добавить рекомендованные источники
  scheduler.py         # периодическая проверка новых статей (расписание)
```

## Поиск новых источников под целевую аудиторию

`news/profile/source_discovery.py` анализирует профиль аудитории (отрасли,
страны ВЭД) и определяет, каких тематических источников не хватает. Каталог
`POTENTIAL_SOURCES` связывает тему аудитории с кандидатами источников.

```bash
# показать темы аудитории и рекомендованные источники
.venv_news/bin/python news/profile/source_discovery_cli.py

# проверить доступность рекомендованных источников и добавить рабочие в sources.json
.venv_news/bin/python news/profile/source_discovery_cli.py --add

# без записи в реестр
.venv_news/bin/python news/profile/source_discovery_cli.py --add --dry-run
```

`--add` проверяет каждый рекомендованный источник (HTTP-статус + число записей
через feedparser) и добавляет в `sources.json` только те, что реально отдают
статьи. Так пул источников растёт под конкретную аудиторию, а не вручную.

## Расписание проверки новых статей

`news/scheduler.py` периодически запускает сбор новостей и ведёт журнал
запусков (`schedule_state.json`). Подходит для демо и Docker — не зависит от
внешнего cron ОС.

```bash
# каждый час, бесконечно
.venv_news/bin/python news/scheduler.py --every 3600

# один проход и выход
.venv_news/bin/python news/scheduler.py --once

# CRON-выражение (минуты часы): каждые 6 часов
.venv_news/bin/python news/scheduler.py --cron "0 */6 * * *"
```

Параметры сбора (`--target`, `--category`, `--out-dir`, `--cache-dir`)
пробрасываются в `dump_large.py`. Журнал запусков виден в
`data/processed/news_bulk/schedule_state.json`.
```

## Профилирование целевой аудитории (тематика батчей)

На основе CSV клиентов (юрлица/платежи) модуль `news/profile/` вычисляет, какие
отрасли, регионы, страны ВЭД и типы клиентов преобладают у целевой аудитории,
и формирует тематический план регулярного батча:

```bash
.venv_news/bin/python news/profile/plan_cli.py            # профиль + план
.venv_news/bin/python news/profile/plan_cli.py --json     # JSON-вывод
```

Сбор с фильтром по аудитории (собирает не всё, а релевантное):

```bash
.venv_news/bin/python news/collect.py --audience-csv news/df_Uid_data_hack.csv
```

Данные CSV читаются локально и НЕ попадают в git (см. .gitignore: `news/*.csv`).
Фильтрация лёгкая (по ключевым словам), без LLM — не тратит бюджет.

## Источники и лицензии

В `sources.json` — пул деловых/официальных/отраслевых лент (ЦБ РФ, Минфин,
Мосбиржа, Интерфакс, РБК, Коммерсантъ, Ведомости, Lenta, Прайм, банковские
и отраслевые ленты). Реестр отфильтрован: включены только реально работающие
ленты (проверены HTTP-статусами), мёртвые/недоступные удалены. Пул можно
расширять без изменения кода: `kind` = `rss` / `json` / `html`, `category` —
группа для фильтрации. Перед добавлением источника проверяйте, что лента
отдаёт 200 и условия её использования (указываем название, не перепродаём
контент, соблюдаем лимиты).

### HTML-листинги: фильтр настоящих новостей

Для `kind="html"` (например, Минфин) парсер выделяет только ссылки, похожие
на статьи, и отбрасывает мусор:

- статические ресурсы — `favicon.ico`, `*.css`, `*.js`, `*.png`, `*.svg` и т.п.;
- навигацию по разделам сайта — `ministry`, `document`, `contacts` и т.п.;
- UI-фильтры/сортировку — `mode_4=default`, `TYPE_ID_4=2`;
- якоря и пустые/корневые ссылки.

Новостная ссылка должна иметь явный признак статьи: query-параметр вида
`<id>_<n>=<цифры>-<slug>` (как `?id_4=40706-gosduma_utverdila_...`) либо слово
`news`/`press`/`announce` в пути. Заголовок при `kind="html"` извлекается из
slug, а не из URL целиком.

Проверка: `news/smoke_test.py` включает тест HTML-фильтра (реальная новость
Минфина проходит, мусор — нет).

При скачивании полного текста статьи (`fetch_article`) заголовок берётся из
метаданных страницы (`<title>`), поэтому для HTML-источников он кириллический
и читаемый, а не транслитерированный slug из URL.

## LLM-подсистема (до сшивки с адаптером пункта 1)

`news/llm/` — доступ к разрешённым моделям и локальный учёт бюджета. Это
подготовка к сшивке: сам пайплайн собирает статьи без LLM, а здесь лежит
клиент для будущего извлечения фактов (выход `EventBundle`).

- `config.py` — чтение ключа/base_url/модели через `os`/`.env`; ключ не в коде,
  в логах маскируется (`sk-QMh******x9g`).
- `model_policy.py` — разрешённые модели из инструкции трека; выбор по задаче.
- `client.py` — тонкий OpenAI-compatible клиент, обработка `Budget has been exceeded`.
- `budget.py` — локальный учёт дневного лимита 500 ₽ (сброс 03:00 МСК).
- `probe.py` — минимальная проверка связи (тратит несколько токенов).

Настройки — в `.env` (не в git): `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`,
`LLM_DAILY_BUDGET_RUB`, `LLM_ENABLED`.

```bash
.venv_news/bin/python news/llm/probe.py                          # проверка связи
.venv_news/bin/python news/llm/probe.py --model deepseek/deepseek-v4.1-flash
```

Замечание: на корпоративной сети оба gateway блокируются (ConnectionReset /
«Сайт заблокирован»), поэтому реальные вызовы LLM работают вне прокси
(дома/с другого доступа). Локальная проверка конфигурации и бюджета работает
везде.

## Чего здесь нет

- NLP, классификации и извлечения фактов — это пункт 1 (агент), выход `EventBundle`.
- Ранжирования под компанию — модуль `ranking/`.
- Позиции банка / аналитики — RAG в `llm/rag/`.
