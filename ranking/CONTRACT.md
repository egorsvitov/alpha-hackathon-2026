# Контракт первого baseline, версия 0.1

Вход ранкера — профиль, построенный `CompanyRepository.get(company_id)`, и уже структурированные события. Вызовы LLM и извлечение из произвольного текста здесь не выполняются.

```python
from ranking.profiles import CompanyRepository
from ranking.events import load_events
from ranking.engine import rank_events

repository = CompanyRepository()
profile = repository.get("U_3263")
events = load_events("data/examples/ranking/events.json")
response = rank_events(profile, events, "2026-10-20T18:00:00+03:00", top_k=5)
```

## CompanyContext

`company_id`, `profile_version`, `synthetic`, `okved.code/name`, `industry`, `products`, `region`, `city`, `countries`, `fts_present`, `revenue.raw/unit/unit_status`, интервальные категории, `graph`, `features`, `missing_fields`, `warnings`.

Продукты: `rko`, `guarantee`, `loan`, `leasing`, `deposit`, `payroll`, `factoring` со значениями true/false/null. `features` — словарь по ID вида `U_3263:products.loan`. У значения есть путь, качество и исходный CSV/поле/номер записи/хэш файла. `graph.status=not_loaded` означает отсутствие расчета, а не отсутствие связей.

Роль пользователя пока не участвует в скоринге. Независимого классификатора отраслей нет: применяется ограниченная авторская группировка разделов ОКВЭД в `profiles.py`, неизвестные коды сохраняются как unknown.

## NewsEvent

Обязательные поля:

```json
{
  "event_id": "test-001",
  "title": "Тестовое изменение стоимости топлива",
  "text": "Вымышленный текст; не реальная новость.",
  "event_type": "fuel",
  "source_id": "synthetic://test-001",
  "synthetic": true,
  "published_at": "2026-10-20T12:00:00+03:00"
}
```

`published_at` может быть null, но такое событие не попадает в текущую выдачу. Даты должны иметь часовой пояс. Дополнительные поля:

- `cluster_id` (по умолчанию event_id), `version` (положительное целое, по умолчанию 1);
- `effective_at`, `observed_at` — дата вступления и появления в системе;
- `industries`, `okved_prefixes`, `regions`, `countries`, `entity_ids` — списки строк;
- `entity_resolution`: unresolved / synthetic / verified.

Известные broad industries перечислены в `profiles.industry_for`; новости и профили должны использовать одну таксономию. Строки стран сопоставляются в верхнем регистре, регионов — без учета регистра. Алиасы языков/написаний пока не разрешаются.

`event_type` свободный: неизвестная тема не вызывает ошибку, но может не получить сигналы. Готовые типы/механизмы описаны в `config/rules.json`. Метки тем и охвата должны поступать от upstream, для демонстрации они заданы вручную.

Версии относятся к существенным изменениям фактов кластера, а не числу перепечаток. Upstream назначает монотонную версию. В исторической выдаче сначала исключаются будущие публикации/наблюдения, затем выбирается высшая доступная версия и последняя публикация внутри нее. Поздняя перепечатка версии 1 не перекрывает уже известную версию 2. Исходная дата события не заменяет дату публикации.

`verified` означает, что upstream действительно имеет разрешенный справочник entity resolution. Сам ранкер такого справочника не создает. Режим `synthetic` допустим только для явно вымышленных событий и маркируется в результате. Локальная передача статуса не является механизмом авторизации — ее обеспечивает backend.

## RankedEvents

На уровне запроса: компания, версия профиля, as_of, версия и SHA-256 правил, SHA-256 нормализованных входных событий, политика окна, предупреждения и пропуски профиля. Хэш событий не зависит от порядка входного списка; изменившиеся факты/правила меняют соответствующий хэш.

- `ranked`: все кандидаты по убыванию score; это еще не финальная лента.
- `feed`: top-K после порога, ограничения повторов темы и скрытия уже показанных версий.
- `excluded`: ID сообщений и причины исключения (включая будущие, неизвестную дату, старую версию и отсутствие сигнала).

Каждая позиция содержит исходное событие, score 0–100, eligibility, список причин с вкладом в score, candidate_channels, использованные признаки с provenance, missing_context, evidence_status и warnings.

Score = ограниченная сверху сумма описанных групп сигналов. Возраст публикации имеет период полуснижения 10 дней, но не создает релевантность без бизнес-сигнала. Окно по умолчанию 30 дней; старое объявление с вступлением в ближайшие 14 дней сохраняется. Два события одной темы в ленте по умолчанию; оценка >=75 позволяет обойти тематический лимит. Все эти параметры — эвристика первой версии.

Продуктовый вклад выбирается как максимум по активным продуктам, чтобы кредит+лизинг не складывались автоматически. Отраслевое совпадение и гипотеза механизма остаются отдельными группами и могут быть коррелированы; веса не обучены и требуют независимой проверки. В выдаче нет вероятности дефолта, финансового ущерба или утверждения о фактических договорных условиях.

## Платежный граф

`attach_payment_graph(profiles, known_company_ids, path)` читает CSV потоком, сохраняя только ребра выбранных компаний. Исключаются самопереводы и все повторяющиеся направленные пары: период неизвестен и суммирование может удвоить агрегаты. Неполные узлы сохраняются. Суммы считаются через Decimal; в JSON исходный объем записывается строкой, доля — числом.

Доля рассчитывается отдельно по входящему/исходящему наблюдаемому потоку. Покрытие профилей — доля уникальных соседних ID, а не строк или сумм. Внешних названий/ИНН нет. Graph-probe в demo — отдельный синтетический сценарий, который не входит в метрики ленты.

При подключении графа profile_version дополнительно включает версию агрегации и хэш платежного файла, чтобы кэш не спутал профили с разными платежными снимками.
