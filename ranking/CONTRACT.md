# Переход после удаления старого ранкера

`ranking.engine.rank_events`, `load_rules`, `candidate_report` и CLI `rank/demo` удалены. Вызовы старого API больше не поддерживаются. Возвращать вместо них пустую ленту или фиктивный score нельзя.

Сохранены контракты компаний, B6, immutable snapshots и схемы старых результатов для чтения исторических артефактов. B6 v0.2 сохраняется без downgrade; номер версии события — integer, timestamps содержат секунды и часовой пояс.

Новый выход проектируется как [ImpactCandidateBatch v1](../docs/retriever/contract.md). Пока это спецификация, не реализованная функция. Этот объект нельзя передавать существующему backend-адаптеру старого `feed`.

`llm.agent analyze` временно работает только с явно переданным `--relevance <file.json>` в fixture-режиме. Это вход старого аналитического контракта для диагностики, а не автоматический отбор. При переходе аналитика на новый контракт Relevance будет исключён из этого пути.

Backend `ranking_adapter.py` остаётся адаптером старой структуры, а не новым ретривером. Его явный отказ от B6 v0.2 и fallback поиска snapshot без hash требуют отдельной замены в задаче интеграции. Нельзя считать backend уже совместимым с новым контрактом.
