# Отчет: первый рабочий ранкер

20 октября 2026 года. Компонент реализован локально в ветке `ml/ranking-baseline`. Это первый проверяемый baseline, а не обученная модель или законченный продукт.

## Что реализовано

- Нормализатор настоящего CSV компаний: продукты true/false/unknown, ОКВЭД, категории численности и происхождение признаков. Конфликтные ID отклоняются.
- Валидация структурированных событий, временной фильтр, объединение перепечаток и выбор наблюдаемой версии кластера.
- Каналы отрасли, продуктов, региона, стран, прямых entity IDs, платежных контрагентов и слабого текстового совпадения.
- Объяснимый score с версиями/хэшами правил и входных событий; причины связаны с признаками исходного профиля.
- Сборка ленты с порогом, разнообразием тем и учетом уже показанных версий.
- Потоковый расчет платежных соседей, долей и покрытия с исключением самопереводов и неоднозначных повторов.
- CLI для профиля, ранжирования и демонстрации; Python API и контракт для backend.
- 20 синтетических сообщений, 16 доступных на момент теста кластеров, 48 черновых меток для трех реальных профилей.

## Как посмотреть результат

```bash
python3 -m ranking demo
python3 -m ranking demo --with-payments --output data/processed/ranking/with_graph
python3 -m unittest discover -s ranking/tests -v
python3 -m ranking.validate_data
```

Основной читаемый результат: [demo.md](../data/processed/ranking/with_graph/demo.md). Машинный вывод: [feeds.json](../data/processed/ranking/with_graph/feeds.json). Эти локальные результаты исключены из Git; команды воспроизводят их при наличии исходных CSV.

## Что проверено

**39 unit/behavior/CLI-тестов прошли.** Они не требуют банковских данных и создают временные синтетические CSV. Среди сценариев: конфликтные ID, неизвестные продукты, узкий ОКВЭД, неверные даты, будущая публикация/ингестия, поздняя перепечатка старой версии, пустой вход, стабильные tie-breaks, смена профиля, сохранение provenance, неизвестные узлы, самопереводы, неоднозначные платежные пары, расчет метрик и неполная разметка.

Полная таблица: 85,514 уникальных ID; успешно нормализовано 85,513; исключен конфликтный `U_428697`. На 100 других/разных компаниях прошли проверки инвариантов ранжирования. Это не оценка полезности ответов для этих компаний.

Укрупненная авторская карта пока не определяет отрасль для 16,366 компаний; исходный ОКВЭД и описание сохраняются. Это ограничение покрытия, а не ошибка чтения CSV.

Платежи: прочитано 1,380,585 строк, выбранные компании затрагивают 1,278 строк, исключено 2 самоперевода. В этой выбранной подвыборке неоднозначных повторных пар нет; политика их исключения отдельно проверена на синтетическом тесте.

Локальный замер чистого ранжирования при загруженных профилях и 20 входных сообщениях: p50=0.509 мс, p95=0.596 мс на 100 запросах. CSV, API, LLM, парсер и сеть в эти времена не входят; это не production-SLO.

## Черновая оценка рекомендаций

**Метки и правила подготовлены одним агентом. Независимой экспертной оценки нет.** Результаты ниже служат проверкой согласованности маленького демонстрационного набора, а не доказательством качества на новых реальных новостях.

| Компания | nDCG@5 ленты | Precision@5 | nDCG@5 по свежести |
|---|---:|---:|---:|
| U_3263 | 1.000 | 1.000 | 0.579 |
| U_44792 | 0.975 | 0.600 | 0.172 |
| U_1941 | 1.000 | 1.000 | 0.058 |

На этих метках все события класса 3 попали в кандидаты. Есть отдельный тест, где неподдерживаемая тема действительно теряется: оценка показывает пропуск, а не скрывает его. Метрики не настроены на достижение какого-либо заявленного организаторами порога.

## Что остается сделать

1. Аналитик независимо проверяет черновые метки и готовит скрытые семейства событий, включая косвенные и пограничные случаи.
2. Другой ML/backend предоставляет реальное извлечение темы, участников и охвата из нового текста; сейчас вход структурирован заранее.
3. Расширить и проверить ОКВЭД-таксономию; простой lexical fallback не заменяет семантику и не понимает отрицание.
4. Получить семантику единиц/периода платежей и разрешенное сопоставление имен с ID. До этого реальный графовый канал не обещается.
5. Сравнить эмбеддинги и/или обучаемый ранкер с текущим baseline после появления независимой разметки.
6. Подключить к backend и downstream LLM. Параметры договоров, места операций, реальная роль пользователя и денежный эффект пока неизвестны.

## Расход и публикация

Новых сторонних Python-зависимостей и моделей не добавлено. LLM API не вызывался, расход командного ключа — 0 токенов / 0 ₽. GPU для этого baseline не требуется. Исходные CSV не менялись; результаты с реальными профилями и графом исключены из Git. Код и синтетические fixtures подготовлены для обычного коммита.
