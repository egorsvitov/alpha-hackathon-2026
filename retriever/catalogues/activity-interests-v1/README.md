# Пять поисковых интересов на деятельность

Каталог отдельных поисковых тем по всем видам деятельности из зафиксированного
локального списка. Темы описывают возможные интересы бизнеса, а не установленные
факты об отдельной компании. Наличие темы кредитования не доказывает наличие
кредита, а тема экспорта сама по себе не подтверждает экспортную деятельность.

## Файлы

- `activities.json` — исходные коды и названия деятельностей без данных компаний.
- `catalogue.json` — пять отдельных интересов для каждой деятельности.
- `catalogue.csv` — те же интересы в плоской таблице UTF-8 BOM для просмотра.
  При открытии кода ОКВЭД в электронной таблице задайте столбцу текстовый тип,
  чтобы приложение не преобразовало код в число или дату.
- `reviews.json` — проверка каждой деятельности другим агентом, исправления и
  оставшиеся замечания. Это не ручная человеческая разметка релевантности.
- `manifest.json` — модели, количество записей, диагностика и SHA-256 артефактов.
- `EDITORIAL_GUIDE.md` — единая инструкция генераторам и проверяющим.

В каждом интересе: `slug`, `title`, `description`, `applicable_when`. Идентификатор
интереса строится как `<okved_code>/<slug>`. Поле `description` содержит
самостоятельный поисковый текст, без смешивания пяти направлений в один вектор.
Непустое `applicable_when` требует проверки применимости к конкретному бизнесу;
такие темы нельзя автоматически представлять как подтверждённые экспозиции.

## Подготовка и проверка

Три генератора `gpt-6-luna`, reasoning `medium`, готовят непересекающиеся пакеты.
Затем три независимых проверяющих `gpt-6.1-sol`, reasoning `medium`, читают все
записи, исправляют ошибки и сохраняют замечания. Главный агент собирает результат
и выполняет проверки состава, формата и повторов. Каталог имеет статус
`agent_reviewed_hypotheses`; человеческого утверждения нет.

Проверить готовый каталог из корня репозитория:

```bash
.venv/bin/python -m retriever.experiments.activity_interest_catalogue --validate-only
```

Команда не использует модель, GPU, API, исходные новости или таблицы компаний.
Редакционное качество нельзя доказать одной структурной валидацией: журнал
смысловой проверки и оставшиеся неоднозначности находятся в `reviews.json`.

Пересборка из локальных промежуточных проверенных пакетов:

```bash
.venv/bin/python -m retriever.experiments.activity_interest_catalogue
```

Промежуточные файлы находятся в игнорируемой Git папке
`data/processed/retriever/activity-interests-v1/work/`. Финальные JSON/CSV и журнал
проверок самодостаточны; промежуточные файлы не нужны для использования каталога.

## Граница этапа

На этом этапе эмбеддинги и графовые интересы компаний не вычисляются, runtime
ретривера не меняется. Для будущего кодирования нужен тот же закреплённый профиль
BGE-M3, что и у новостей; пять текстов следует кодировать раздельно. Каталог
общий: компании могут ссылаться на интересы своей деятельности без физического
дублирования всех текстов и векторов.

Исходные новости, идентификаторы компаний, платежи, рабочие базы, ключи и веса
моделей в эти артефакты не включены.
