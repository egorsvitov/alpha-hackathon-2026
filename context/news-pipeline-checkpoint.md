## Рабочая схема

Новости → ArticleInput → B2 (неизменяемая версия, SQLite) → B3
(discovery → предметные пакеты до 3 упоминаний → сборка кандидатов) → B4
(цитаты, числа, периоды, алиасы) → B5 (каталог событий) → B6 (EventBundle v0.2,
JSONL + manifest). Вариант B дополнительно проверяет все принятые B4 утверждения
пакетами до двух и пересобирает отдельную выдачу из отобранных кандидатов A.

Последний формат оснований — `span-ids.v1`: модель выбирает готовые диапазоны
`P1.S1`–`P1.S2`, код восстанавливает цитату и Unicode-координаты. Контракты
B1/B3 b3.1/B4/B6 не изменены; SQLite-схема 4. Публикация явная, текущие чтения
блокируются, если входные редакции или каталог устарели.

## Нерешённые проблемы, к которым вернуться после уборки

1. Пустая строка таблицы с пятью колонками блокирует весь шестиколоночный блок:
   13 упоминаний отложены до API. Нужен явный разбор служебных строк.
2. B4 не поддерживает `б/с` и часть безразмерных коэффициентов/кратных сравнений:
   четыре кандидата потеряны. Нельзя подменять «в N раз» произвольным процентом.
3. Модель смешивает ID абзацев и предложений в context_fragment_ids;
   иногда переворачивает границы. Ошибки теперь изолированы по упоминанию.
4. Значения полей всё ещё перефразируются («сентябрь» вместо «в сентябре»);
   ID доказательств исправили переписывание цитат, но не исходных выражений.
5. Модель ошибочно исключает явно названный базовый сценарий; встречаются
   неправильные роли, например comparison_period="на уровне".
6. Проверяющему не хватает определений категорий/ролей; применимость пустого
   participants слишком строга. Девять отказов B не равны девяти ошибкам A.

Количество событий не является метрикой качества. Разметка —
`single_annotator_draft`, три статьи — набор разработки. Числа не доказывают
качество B3 или всей системы; точные цитаты не доказывают смысл или истинность.

## Границы уборки

Сократить активные способы извлечения, разделить модули по стадиям, дать одну
точку входа CLI и короткую карту запуска/данных. Сохранить внешние контракты,
SQLite-схему, историю и содержательные проверки. Не исправлять одновременно
с реорганизацией перечисленные алгоритмические проблемы и не вызывать API.
Незавершённые изменения сборщиков в news/ не удалять. Файлы локальных данных,
.env, состояния и журналы не перемещать и не добавлять в Git.

## Уборка выполнена в news-pipeline-clean

Код сгруппирован по стадиям; одна CLI-точка входа — `python -m llm.events`.
Удалены исполняемые compact/form/rows, two-stage.v1, независимый legacy,
их отдельные схемы/инструкции и проверки удалённых режимов. Оставлены b3.1,
последняя пакетная схема и содержательные проверки B1–B6.

Изменения представления не являются оценкой качества и не исправляют автоматически

хэши; для возобновления использовать новые планы и команды из README.

Небольшое уточнение адаптера: непустой текст сборщика больше не объявляется полным
оригиналом без подтверждения. Изменение этого метаданного при повторном импорте может
создать новую редакцию согласно обычным правилам B2; старые редакции не переписываются.

Документация: `llm/events/README.md`, `docs/pipeline.md`, `docs/structure.md`
и справочники стадий под `llm/events/docs/`. Ссылки в корневых README обновлены.
Тесты работают с временными БД и управляемыми часами; реальные API-вызовы при уборке
не выполнялись. Старые 11 bundles последнего API-прогона по-прежнему проходят схемы,
проверку архивных цитат и SHA-256 JSONL.
