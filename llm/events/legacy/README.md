# Сохранённый прототип из удалённой news-pipeline

Эта независимая ранняя реализация B2/B3 сохранена при объединении веток, чтобы не потерять чужую работу. Её модели, JSON-состояние и бюджет несовместимы с основным NLP-пайплайном. Она не используется основным пакетом и не является producer B6.

Основные контракты, SQLite, бюджет и обработчики находятся в родительском `llm/events/`; см. [основную документацию](../README.md). Подключение `news/` к основному входу требует явного адаптера: JSONL и модель сборщика не содержат обязательных полей происхождения B1, а пустой текст не является ArticleInput.

Прототип может вызывать LLM через отдельный бюджет `news/llm/`; не использовать его для рабочих вызовов основного NLP. Проверять только офлайн: `python llm/events/legacy/smoke_test.py` с зависимостями `news/requirements.lock`.

Ниже сохранено первоначальное описание прототипа; его заявления о соответствии B6 не заменяют проверку основной схемой.

# llm/events — B2/B3: батч статей → события

Реализация блоков B2 (приём батчей и состояние) и B3 (извлечение утверждений)
из плана NLP-модуля, на базе нашего `news/` (сборщик) и `news/llm/` (клиент,
бюджет, политика моделей).

## Задача

Статьи из `news/` превращаются в каталог событий (EventBundle, контракт B6).
Извлечение делается один раз на статью (независимо от числа компаний) и
кэшируется по содержимому, чтобы не жечь общий бюджет LLM (500 ₽/день).

```text
Article (news/) ─→ B3 extract (LLM) ─→ SourceClaim[] ─→ CanonicalEvent ─→ EventBundle
                       ↑ B2 state (версии, хэши, дедуп)
```

## Структура

```text
llm/events/legacy/
  models.py     # B1: SourceClaim, CanonicalEvent, TimePeriod, Measurement
  state.py      # B2: StateStore — версии статей, хэши, журнал, повторный запуск
  extract.py    # B3: извлечение SourceClaim через разрешённую LLM (промпт + JSON)
  pipeline.py   # оркестратор: process_batch / get_event / export_events
  run.py        # CLI
  smoke_test.py # офлайн-проверка без LLM
```

## Запуск

```bash
# офлайн-проверка логики (не тратит бюджет)
.venv_news/bin/python llm/events/legacy/smoke_test.py

# реальная обработка батча (ВНИМАНИЕ: вызывает LLM, тратит бюджет)
.venv_news/bin/python llm/events/legacy/run.py --limit 20
.venv_news/bin/python llm/events/legacy/run.py --dry-run   # сколько к обработке, без LLM
```

Состояние — `data/processed/events_state/`, каталог — `data/processed/events_catalog.json`
(оба в `.gitignore` как производные данные). Пути меняются флагами CLI.

## Ключевые принципы (из плана B1-B3)

- **Извлечение один раз**: `StateStore.already_extracted` пропускает статьи с тем же
  содержимым и конфигом извлечения (экономит бюджет).
- **Неизменяемые версии**: изменение текста под прежним ID создаёт новую версию
  статьи; цитаты ссылаются на конкретную версию.
- **Идентичность ≠ эквивалентность**: `CanonicalEvent` хранит конфликтующие
  `SourceClaim` раздельно, не сливая их в одно «каноническое» число.
- **Бюджет**: перед каждой статьёй проверяется `news/llm/budget.can_call()`; при
  исчерпании статьи остаются ожидающими (`budget_pending`), а не сжигаются зря.
- **Ошибка одной статьи не останавливает батч**: ошибки пишутся в журнал.

## Ограничения первой версии

- Группировка событий (B5) минимальная: одно событие на статью
  (`event_id = ev:<article_id>`). Полная идентичность событий, дубли/конфликты
  и связанные стадии — отдельный шаг B5.
- Нормализация сущностей/дат/чисел (B4) — на следующем шаге.
- Реальные вызовы LLM требуют сети без корпоративного MITM (на прокси шлюз
  блокируется). Логика и проверки работают офлайн.

## Требуемые зависимости

Модуль переиспользует `news/llm/` (openai, python-dotenv) — отдельные новые
зависимости не нужны. Установка: см. `news/requirements.txt`.
