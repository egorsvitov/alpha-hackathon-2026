# B1–B6: утверждения и каталог экономических событий

Реализованы строгие Pydantic-модели статьи и события, B6 v0.2, явное преобразование v0.1 → v0.2, проверка связей и точных цитат, инструкция разметки и эталонные примеры. [B2](STORAGE.md) добавляет SQLite-архив, версии статей, батчи и состояние заданий. [B3](EXTRACTION.md) добавляет SDK-адаптер и кандидаты с журналом расхода. [B4](NORMALIZATION.md) проверяет цитаты и покрытие полей, нормализует числа/даты/единицы/алиасы и сохраняет пригодную часть статьи. Реальные вызовы и явный repair закрыты до задания тарифов и квоты; по умолчанию B4 работает правилами. [B5](CATALOG.md) добавляет каталог событий, BM25/структурный поиск, версии снимков и ручные решения. Явная LLM-проверка пары сохраняет рекомендацию без применения. [B6](BUNDLE.md) явно публикует версии EventBundle v0.2 из каталога B5 и экспортирует JSONL.

## Запуск

Из корня проекта, Python 3.13 или новее:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r llm/events/requirements.lock
.venv/bin/python -m llm.events.schemas --check
.venv/bin/python -m llm.events.extraction_cli schema --check
.venv/bin/python -m llm.events.normalization_cli schema --check
.venv/bin/python -m llm.events.normalization_cli check
.venv/bin/python -m llm.events.catalog_cli schema --check
.venv/bin/python -m llm.events.catalog_cli check
.venv/bin/python -m llm.events.check_contracts
.venv/bin/python -m unittest discover -s llm/events/tests -v
```

`requirements.txt` фиксирует прямые зависимости, `requirements.lock` — также транзитивные. Pydantic 2.14.1 совпадает с backend lock. `unittest` входит в стандартную библиотеку. Проверки синтетики работают без сети, ключей LLM и внешних исходников; установка зависимостей выполняется отдельно.

## Интерфейс

```python
import json
from llm.events import validate_bundle, validate_grounding, ContractValidationError

payload = json.load(open("docs/b6-examples/v0.2/scenarios.json"))
bundle = validate_bundle(payload)  # типы, ссылки, периоды, доказательства полей
records = json.load(open("llm/events/fixtures/b6_articles.json"))
validate_grounding(bundle, records)  # дополнительно точные версии и цитаты
wire_payload = bundle.model_dump(mode="json")
```

Проверки возвращают валидированную модель либо выбрасывают `ContractValidationError`. `exc.issues` содержит объекты `{code, path, message}`. `path` указывает на место ошибки; для отсутствующей групповой ссылки это путь к соответствующему массиву. Внутренние ошибки Pydantic преобразуются в такой же формат. CLI возвращает код 1 при ошибке; некорректные параметры — код 2.

`validate_bundle` не требует исходного текста и не утверждает, что цитата существует. `validate_grounding` требует `ArticleRecord` для каждого переданного источника и проверяет точную пару ID/версии, метаданные и срез. Отсутствующий источник — ошибка `missing_article`. Координаты — кодовые точки Unicode; JavaScript-индексы UTF-16 напрямую не подходят.

Валидаторы не оценивают истинность публикации, полноту извлечения и смысловое следование текста полю. Дополнительные проверки предотвращают очевидные ложные конфликты между разными сценариями, показателями, единицами или ролями «до/после», но не заменяют смысловую проверку сопоставления B5.

В 0.2 добавлены `Measurement.value_role` и `SourceClaim.scenario`. `upgrade_v01(payload)` из `compatibility.py` проверяет старую JSON Schema, копирует объект и добавляет `reported`/`null`, не пытаясь восстановить отсутствующую семантику. Старые схемы и примеры сохранены. Новые примеры вручную уточняют исходные выражения времени; конвертер их не переписывает. Обратного и неявного преобразования нет.

## Producer B6

`EventBundleService(EventStore(), catalog_id="news")` предоставляет `publish()`,
`get_event(event_id) -> dict` и `export_events(output_path)`. Публикация явная;
чтение базу не меняет. B6 хранит собственные версии и связь с версиями B5.
Текущая SQLite-схема — 4; базы версий 1–3 требуют явной миграции с backup.

Полная последовательность миграции, подготовки B5 и публикации находится в
[инструкции B6](BUNDLE.md). Общий валидатор `ranking/b6.py` принимает v0.1
и v0.2 без неявного понижения версии. Новый `retriever/` использует B6 v0.2;
его выход — пакет кандидатов для аналитика, не legacy ranking feed.
Старые схемы и примеры сохранены.

## Разметка

- [Правила b1.1](ANNOTATION.md): атомарность, все 11 типов, модальность, отрицание, сценарии, время, доказательства и неопределённые связи.
- [Начальный словарь](vocabulary.json): факторы, отрасли, роли, единицы, признаки идентичности и алиасы. Это данные для B4/B5; алгоритм разрешения сущностей не реализован.
- `fixtures/synthetic.json`: 20 самостоятельных вымышленных статей, 22 утверждения, 19 событий. Покрывает дубли, конфликт, разные даты/авторов, прогноз/решение, стадии, диапазоны, проценты/пункты, до/после, сценарии, два показателя, неизвестные данные, несколько предложений и emoji/исправление.
- `docs/b6-examples/v0.2/`: семь примеров для участника аналитики. Их исходники находятся в `fixtures/b6_articles.json` и тоже целиком синтетические.

Для локальной разметки предоставленных 15 пересказов:

```bash
.venv/bin/python -m llm.events.check_contracts \
  --gold data/context/events/development-gold.json \
  --articles ../alpha-context/articles.json
```

`--gold` — сохранённая ручная разметка с полными текстами, `--articles` — исходная выгрузка для сверки полного набора ID и хэшей. Оба пути задаются явно. Без `--articles` проверяются внутренние хэши разметки, но не соответствие внешней выгрузке. Любой файл можно передать из другого каталога; абсолютные пути автора в коде не зашиты.

Локальный эталон содержит 15 статей, 73 утверждения и 66 кандидатных событий, с типами, измерениями, временем, доказательствами, ограничениями и 10 ожидаемыми связями. Там, где соответствие неизвестно, `expected_event_id=null`; отдельный технический контейнер не считается установленной идентичностью. Даты и исходные тексты не менялись. Это один размеченный набор разработки, не оценка способности работать на новых новостях. Данные и локальный сценарий авторства находятся в игнорируемом `data/context/events/`, в Git не добавлены.

Проверки требуют точного совпадения SHA-256 всего канонического `ArticleInput`, включая метаданные и значения по умолчанию; изменение текста или даты требует повторной проверки разметки. Результат имеет статус `single_annotator_draft`: независимый смысловой просмотр ещё не выполнен. Extraction F1 не выводится из контрактных проверок. B5 отдельно оценивает сопоставление заданных утверждений; результаты и ограничения описаны в CATALOG.md.

## Изменение схем и синтетических данных

Изменить модели, затем явно обновить артефакты:

```bash
.venv/bin/python -m llm.events.schemas
.venv/bin/python -m llm.events.fixtures.make_synthetic
.venv/bin/python -m llm.events.fixtures.make_b6_examples
```

`schemas --check` обнаруживает рассинхронизацию с моделями и ничего не записывает. JSON Schema проверяет форму; ссылочная целостность, сравнение дат/диапазонов, уникальность ID, точность координат и покрытие доказательствами проверяются кодом. При несовместимом изменении уже переданного B6 требуется новая версия и обновление документации потребителей.

## Для участника аналитики

Использовать [контракт B6 v0.2](../../docs/b6-event-contract.md). Вход — `EventBundle + профиль компании + релевантность + роль/as_of`; банковские доказательства получаются отдельно из RAG. Сценарии и значения до/после доступны структурно. Действующие интерфейсы backend/frontend и выходная схема `Insight` этим блоком не менялись.

## Прототип из параллельной ветки

Ранняя альтернативная реализация сохранена отдельно в [legacy/](legacy/README.md). Её модели и JSON-состояние не импортируются основным пакетом; для B1–B5 использовать API этой документации. Сборщик `news/` принят из удалённой ветки, но адаптер его JSONL к строгому ArticleInput ещё не реализован.
