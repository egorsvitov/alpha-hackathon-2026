# Карта кода и решения уборки

Все стадии используют одни контракты и SQLite. Отдельные папки обозначают ответственность,
а не отдельные сервисы. Для обычной работы достаточно README и `python -m llm.events --help`.

| Стадия | Файлы, с которых начать | Почему сохранено |
|---|---|---|
| Контракты | `contracts/models.py`, `validation.py`, `compatibility.py` | Стабильный B6 v0.2, точные основания, совместимость v0.1 |
| Архив | `storage/store.py`, `schema.py`, `migration.py` | История редакций, атомарность, аренда, безопасное возобновление |
| Импорт сборщика | `storage/news_adapter.py` | Явная граница JSONL сборщика и строгого ArticleInput |
| Простой B3 | `extraction/protocol.py`, `runner.py` | Парсер общего b3.1 и минимальный путь для отладки |
| Пакетный B3 | `extraction/staged.py`, `service.py`, `staged_models.py`, `prompts.py` | Последний проверяемый вариант извлечения, аудит покрытия и A/B |
| Основания | `extraction/fragments.py`, `references.py`, `transport.py` | Точные срезы по ID, чтение полного Markdown-конверта без ремонта JSON |
| Сеть и расход | `extraction/provider.py`, `budget.py`, `credits.py` | Один вызов, бюджет и неизвестный расход после сбоев |
| Нормализация | `normalization/core.py`, `numbers.py`, `dates.py`, `service.py` | Числа/периоды/организации и сохранение пригодной части статьи |
| Каталог | `catalog/matching.py`, `search.py`, `grouping.py`, `service.py` | Идентичность прежде сравнения, защита от транзитивного слияния, история |
| Публикация | `publication/features.py`, `service.py`, `export.py` | Детерминированные метки/качество, публичные версии и атомарный JSONL |

`models.py` внутри стадий задаёт форму данных; `cli.py` содержит только команды стадии.
`extraction/admin_cli.py` обслуживает простой B3 и обычный бюджет;
`extraction/cli.py` — пакетный эксперимент. `publication/builder.py` сохраняет адаптер
публичной функции build_bundle для существующих потребителей.

## Что удалено из активного дерева

- Независимый `legacy/` со своим JSON-состоянием, моделями и исполнителем: не использовался
  основным каталогом и создавал второй несовместимый pipeline.
- `compact.v1`, `form.v1`, `rows.v1`: пройденные варианты LLM-ответа, отдельные
  компиляторы, схемы, тесты и инструкции. Последний пакетный вариант использует
  общий стабильный b3.1 и не зависит от них.
- `two-stage.v1`, отдельный pilot CLI, replay/reassembly старых форматов: исследовательские
  команды, которые больше не нужны для текущего контролируемого A/B.
- Ручной `news_adapter_test.py`, требовавший внешний корпус: заменён воспроизводимым
  unittest с временным JSONL и проверкой настоящего импорта.
- Несколько перекрывающихся инструкций B3: заменены одной `docs/extraction.md`.

Общие функции сегментации и разбора конверта вынесены из удалённых экспериментов.
Кредитный счётчик и ограничения сохранены, потому что текущий API-тест использует их.
Список старых candidate_format остаётся допустимым в ProviderProfile **для чтения
истории**; обычный runner явно отклоняет запуск удалённого формата. Новый default
простого B3 — b3.1. Пакетная схема выбирается отдельной командой `extract`.

## Что сохранено намеренно

Хранилище, миграции, бюджетные резервы, heartbeat, stale-проверки, ручные решения B5,
история публикаций и содержательные тесты занимают значительную часть кода. Они защищают
архив и расход, поэтому не удалены ради числа строк. Опциональный repair B4 и LLM-проверка
пары B5 остаются явными операциями; обычная обработка их не запускает.

Публичные схемы B1/B3/B4/B6, примеры EventBundle v0.1/v0.2 и SQLite-схема 4 сохранены.
Новая структура не требует миграции базы. Основные Python-импорты из `llm.events`
остались; импорты конкретных подмодулей и старые команды `-m` нужно обновить по README.
Изменение кода меняет хэши планов и конфигураций; старую попытку не переименовываем
в новую и исторические результаты не пересчитываем текущими правилами.

Исходный snapshot рабочего дерева, включая чужие незакоммиченные изменения, находится
локально в `data/processed/events/cleanup-checkpoint/`. Результаты API и исходные статьи
остались в прежних игнорируемых каталогах. Сборщики в news/ не перестраивались.

## Проверка изменений

`python -m llm.events check` сверяет все активные схемы с моделями и проверяет
синтетические контракты, B4 и B5. `unittest discover -s llm/events/tests` проверяет
ошибки провайдера, бюджет, версии, сопоставление и B6. `demo` проходит полный A/B
локально с сохранением результатов; повтор должен использовать кэш.

Следующий функциональный этап — исправление проблем последнего API-прогона,
перечисленных в [checkpoint](../../../context/news-pipeline-checkpoint.md).

Измерение уборки (включая исходные незакоммиченные файлы): верхний уровень — 56 → 4
Python-файла; исполняемый Python без tests/fixtures — 9760 → 7824 строки (−20%);
весь Python — 14124 → 11696 строк; схемы — 34 → 27 файлов. Число строк не сокращалось
уплотнением кода или удалением проверок сохранённых возможностей.

Адаптер сборщика теперь консервативно ставит is_full_original_text=false. При повторном
импорте это уточнение метаданных может создать новую версию B2; архив не переписывается.
