# Смысловая группировка исходных текстов

Эксперимент `semantic-groups.v1`: короткая новость целиком или фрагмент длинной
новости → локальный эмбеддинг → группы для совместного чтения. Извлечение
упоминаний и подтверждение идентичности событий здесь не требуются.
Группа не является EventBundle или утверждением, что все тексты об одном событии.
Старый режим `python -m llm.event_pipeline` сохранён.

## Что сравнивается

Оба варианта используют одни векторы и complete-link иерархическую группировку:
каждая пара внутри группы должна иметь оценку не ниже порога.
Это предотвращает объединение по одной цепочке A–B–C при слабой связи A–C.

- `semantic`: `E = max(0, cosine)`.
- `semantic_time`: `E * ((1-alpha) + alpha * 2**(-gap_days/half_life_days))`.

По умолчанию threshold=0.75, alpha=0.4, half_life_days=7 — экспериментальные
начальные значения, не подобранные пороги качества. Дата публикации не объявляется
датой события. Неизвестная дата не штрафует. Для даты без времени сохраняется
интервал календарных суток Europe/Moscow; gap — расстояние между интервалами.
Результат не является вероятностью. Метаданные участников пока не добавляются
как отдельный сигнал; это следующий вариант после сравнения первых двух.

## Установка и запуск

Требуются базовые зависимости проекта (Pydantic v2). Для реального локального
вычисления дополнительно установить `semantic/requirements.txt`, желательно
в отдельное окружение: PyTorch и веса модели могут занимать много места.
Диапазоны версий отделены от прежнего backend lock; фактические версии библиотек
и неизменяемая ревизия модели сохраняются в результатах. Для воспроизведения
используйте те же версии, устройство и backend. Одинаковые оценки при разных
реализациях complete-link могут разрешаться по-разному; backend не менять при
сравнении вариантов.

```bash
python -m pip install -r llm/events/requirements.lock
uv pip install --python .venv/bin/python --torch-backend cpu \
  -r llm/event_pipeline/semantic/requirements.txt

python -m llm.event_pipeline.semantic plan \
  --corpus data/processed/events/news-corpus-v1 \
  --document-ids data/processed/event_pipeline/pilot-v1/document_ids.json \
  --output data/processed/event_pipeline/semantic-pilot
```

Без `--document-ids` выбирается весь корпус. Состав фиксируется до настройки
параметров. Manifest и хэши статей проверяются; несколько редакций одной статьи
требуют явного выбора. Новый состав или размер фрагментов — новый каталог.
Технический Telegram-заголовок не включается в представление. Исходные координаты
в Python Unicode и полные документы сохраняются. Длинные абзацы делятся без
переписывания символов; табличный текст не интерпретируется как восстановленная таблица.

Закреплённая ревизия BAAI/bge-m3:
`5617a9f61b028005a4858fdac845db406aefb181`. `main` не принимается.
Первое скачивание весов разрешается отдельным `--allow-download`.

```bash
python -m llm.event_pipeline.semantic embed \
  --run data/processed/event_pipeline/semantic-pilot \
  --model BAAI/bge-m3 --revision 5617a9f61b028005a4858fdac845db406aefb181 \
  --device cpu --allow-download --batch-size 16 --max-batches 100

python -m llm.event_pipeline.semantic compare \
  --run data/processed/event_pipeline/semantic-pilot \
  --output data/processed/event_pipeline/semantic-pilot-comparison \
  --backend scipy --threshold 0.75 --alpha 0.4 --half-life-days 7
```

`embed` безопасно повторяется: точные совпадения текста/профиля берутся из SQLite.
Одинаковый текст разных источников вычисляется один раз, но источники и единицы
остаются раздельными. Завершённый батч сохраняется одной транзакцией. При ошибке
нет автоматического повтора; после аварии незаписанный локальный батч можно
пересчитать. Ошибка длины токенов останавливает этап без скрытого усечения:
создайте план с меньшим `--max-chars`. Учёт токенов включает специальные токены.
Одновременная запись одного запуска запрещена файловой блокировкой.

Сетевых chat API-вызовов здесь нет, общий журнал их квоты не расходуется.
Время и число локальных батчей/токенов сохраняются, это не расход денег провайдера.
LLM-обобщение запускается отдельно после локального сравнения; инструкция ниже.
Интерактивная визуализация остаётся следующим этапом.

## Масштаб и диагностика

`scipy` использует NumPy для матрицы косинусов и SciPy complete-link. Память и
сложность группировки квадратичны по числу фрагментов. Защитные пределы:
5000 единиц и оценка 40*N² байт не выше 512 МиБ. Это оценка рабочих матриц,
не гарантированный предел RSS процесса (модель и Python используют память отдельно).
Превышение не обрезает данные; требуется уменьшить корпус или явно поднять пределы
`--max-units`/`--max-matrix-mb` после оценки ресурсов.
`reference` — реализация стандартной библиотекой для тестов, максимум 512 единиц.

Экспорт атомарно создаёт новый каталог и никогда не заменяет готовый:

- `documents.jsonl`, `units.jsonl`: оригиналы, координаты, временная точность.
- `vectors.jsonl`: нормализованные векторы с ID, пригодные для будущей проекции.
- `semantic.groups.jsonl`, `semantic_time.groups.jsonl`: все группы, включая одиночные.
- `*.neighbors.jsonl`: ближайшие соседи с cosine, временным расстоянием,
  множителем и итоговой оценкой; число соседей задаёт `--neighbors`.
- `report.json`: покрытие, размеры результата, число батчей/токенов и время.
- `manifest.json`: параметры, модель, версии библиотек/кода и SHA-256 файлов.

Полный набор векторов позволяет позднее строить проекцию и исследовать расстояния,
не запрашивая модель снова. Нулевые входы поддержаны; документы без пригодного
текста перечисляются отдельно. Число групп и одиночек не является метрикой качества.
Для проверки качества понадобится отдельная ручная разметка большого набора.

## Проверки

```bash
python -m unittest llm.event_pipeline.tests.test_semantic
```

Тесты не скачивают веса и не используют сеть: известные векторы проверяют время,
цепочки похожести, сохранение координат, кэш, возобновление и атомарность батча.
Это проверка алгоритма и инфраструктуры, а не качества BGE-M3 на наших новостях.

Документация зависимостей:
[SentenceTransformer](https://www.sbert.net/docs/package_reference/sentence_transformer/model.html),
[complete linkage](https://docs.scipy.org/doc/scipy/reference/generated/scipy.cluster.hierarchy.linkage.html),
[BGE-M3](https://huggingface.co/BAAI/bge-m3).

Для передачи большого эксперимента на GPU: [GPU_HANDOFF.md](GPU_HANDOFF.md).

## GPU-эксперимент и обобщение групп

Воспроизводимые выборка, замеры RSS/VRAM, перебор параметров, оценка явных пар,
черновая диагностика групп и упаковка локального архива описаны в
[инструкции эксперимента](../../../scripts/semantic_gpu/README.md).

Отдельный runner обобщения — `python -m llm.event_pipeline.semantic.summary`.
Он использует транспорт и heartbeat существующего runtime, выделенный неизменяемый
журнал с пределом до 200 попыток и один запрос на группу без автоматических
повторов. Исходники, запросы, ответы и ошибки остаются в локальном каталоге.
Формат и существование ссылок проверяются отдельно от смысловой поддержки.
Состав групп не меняется по ответам модели. Старые журналы квоты не сбрасываются.
Ключ читается только из `LLM_API_KEY` или локального `llm/events/.env`.
