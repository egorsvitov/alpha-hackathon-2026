# Задача агенту: большой GPU-эксперимент

## Цель и точка входа

Прими переданный коммит из ветки `news-pipeline-clean` репозитория
`egorsvitov/alpha-hackathon-2026`. Сначала прочитай этот файл, `README.md` рядом и
`context/event-pipeline-progress.md`. Сохрани чужие незакоммиченные изменения;
для своей работы создай ветку `news-pipeline-gpu-experiment` от переданного коммита.
Если есть сомнение в актуальности ветки, ориентируйся на SHA из сообщения владельца,
а не на произвольный свежий main.

Цель: измерить смысловую группировку на большом зафиксированном корпусе,
сравнить влияние времени, измерить ресурсы и подготовить данные для визуализации.
Пользователь разрешил скачивать модели/зависимости и делать реальные API-вызовы.
Экономия вызовов не должна заменять эксперимент, но каждый запуск имеет конечный
лимит, полный журнал и не делает скрытых повторов. Не публикуй тексты, ключи и базы
в Git; исходные документы и результаты остаются в игнорируемом data/processed/.

Готовы `semantic plan/embed/compare`, CPU/CUDA SentenceTransformer, кэш и экспорт.
Обязательного LLM-извлечения перед эмбеддингами нет. Группы — наборы материалов для
совместного чтения, не подтверждённая идентичность событий. Старый B1–B6 не менять.
LLM-обобщение новых semantic-групп и их интерактивная визуализация ещё не реализованы.
Старый `llm.event_pipeline.report` читает другой контракт и для них не подходит.

## Данные и окружение

Корпус отсутствует в Git. Владелец передаёт отдельно `semantic-corpus.tar.gz` и
`semantic-corpus.tar.gz.sha256`. Архив содержит только manifest и documents.jsonl
снимка prepared-news.v1, без API-ключей и рабочих баз. Проверь SHA-256, распакуй из
корня проекта. Ожидается `data/processed/events/news-corpus-v1/`: 3621 документ.
План дополнительно проверяет хэши статей и исходных текстов. Если архив не передан,
сначала подготовь окружение и тесты, затем запроси архив; не подменяй его 43 текстами.
API-ключ передаётся владельцем отдельно или уже находится в LLM_API_KEY/.env;
никогда не печатай его, не включай .env в архивы и отчёты.

Используй отдельное окружение с Python 3.12 или 3.13. Не копируй .venv с другой машины.
Проверь `nvidia-smi` и совместимость драйвера. При NVIDIA GPU пример установки:

```bash
uv venv --python 3.13 .venv_events
source .venv_events/bin/activate
uv pip install --python .venv_events/bin/python -r llm/events/requirements.lock
uv pip install --python .venv_events/bin/python --torch-backend auto \
  -r llm/event_pipeline/semantic/requirements.txt
python -c 'import torch; print(torch.__version__, torch.version.cuda); print(torch.cuda.is_available())'
```

Если auto не подходит драйверу, выбери поддерживаемую CUDA-сборку PyTorch по
официальной документации. Не продолжай GPU-замеры при cuda.is_available()==False.
Запиши GPU, VRAM, драйвер, CPU, RAM, Python и `uv pip freeze` в локальный отчёт.
Реальный backend пока PyTorch, не ONNX. Используй модель BAAI/bge-m3, ревизию
`5617a9f61b028005a4858fdac845db406aefb181`. Модель скачивается через --allow-download;
векторы сохраняются и не вычисляются заново при повторном compare.

```bash
python -m unittest discover -s llm/event_pipeline/tests
python -m unittest discover -s llm/events/tests
python -m llm.event_pipeline check
```

## Выборка и основной проход

1. Проанализируй распределение источников, дат, длин и точных копий корпуса.
   До подбора порогов сохрани selection.json с 1000 document_id. Используй
   фиксированный seed=20261023, стратификацию по источникам/неделям; не допускай
   доминирования одного биржевого источника. Включи связанные публикации из разных
   источников, однотипные разные события и случайный фон. Сохрани алгоритм выборки
   и доли источников; не выбирай только удачные примеры или только соседей BM25.
2. Полностью обработай эти 1000 документов. Зафиксируй train/dev/test по сюжетам
   вместе с перепечатками для ручной оценки; если автоматической разметки нет,
   выдели отдельные семьи вручную до настройки порога. Не выдавай весь корпус за
   независимый тест. Если хватает ресурсов, расширь расчёт векторов на весь снимок.
3. После plan проверь число фрагментов: квадратичная группировка ограничена именно
   фрагментами, не статьями. Не уменьшай выборку скрыто при превышении лимита.

```bash
python -m llm.event_pipeline.semantic plan \
  --corpus data/processed/events/news-corpus-v1 \
  --document-ids data/processed/event_pipeline/gpu-experiment/selection.json \
  --output data/processed/event_pipeline/gpu-experiment/run

python -m llm.event_pipeline.semantic embed \
  --run data/processed/event_pipeline/gpu-experiment/run \
  --model BAAI/bge-m3 --revision 5617a9f61b028005a4858fdac845db406aefb181 \
  --device cuda --allow-download --batch-size 16 --max-batches 1000

python -m llm.event_pipeline.semantic compare \
  --run data/processed/event_pipeline/gpu-experiment/run \
  --output data/processed/event_pipeline/gpu-experiment/comparison-default \
  --backend scipy --threshold 0.75 --alpha 0.4 --half-life-days 7
```

Сначала проверь небольшой GPU-батч и подбери batch-size по VRAM; затем продолжай
тот же run. OOM не должен автоматически повторять запрос бесконечно: сохрани ошибку,
явно уменьши batch-size и возобнови из кэша. Профиль устройства/модели не менять
внутри run. Проверяй complete=true; не запускай compare на неполных векторах.
При превышении токенов не обрезай текст, создай новый план с меньшим max-chars.

Код оценивает рабочую память матриц как 40*N² байт; по умолчанию предел 512 МиБ
и 5000 единиц. Это не полный RSS. Подними --max-units/--max-matrix-mb только после
оценки RAM, сохрани новые значения. CUDA ускоряет embedding; SciPy-группировка на CPU.

Замерь холодное скачивание отдельно от загрузки весов и inference. Сохрани время,
тексты/сек, токены/сек, число фрагментов, длины токенов, пик RAM/VRAM, размер кэша
и экспорта. Перезапусти embed и подтверди new_vectors=0. Измерение VRAM и RSS добавь
обёрткой вокруг запуска, если встроенного отчёта недостаточно.

## Сравнение и ручная диагностика

На тех же векторах сравни threshold {0.65,0.75,0.85}, затем при выбранном на dev
пороге alpha {0.2,0.4,0.6} и half-life-days {1,7,30}. Каждый compare создаёт новый
каталог; не перезаписывай результаты. Не называй максимум числа групп качеством.

Вручную проверь минимум 60 групп/случаев, включая одиночки, большие группы,
различающиеся между вариантами, разные даты одного сюжета и похожие разные события.
Сохрани sample seed, ID, основания и single_annotator_draft. Размечай явно:
полезно читать вместе / посторонний материал / недостающая связь / неопределённо.
Не оценивай по требованию строгого same_event. Неразмеченные пары не отрицательные.
Отчёт должен различать качество групп и полезность последующего обобщения.

## API-проверка обобщения (после готового локального сравнения)

Если доступен API, реализуй небольшой отдельный runner обобщения semantic-групп,
переиспользовав транспорт, heartbeat и учёт запросов существующего runtime.
Это новая часть кода, а не существующая команда compare. Не возвращай обязательную
LLM-проверку каждой пары. Не переписывай состав групп на основании ответа модели.

Обработай не менее 50 разнообразных групп, если они есть. Один вызов на группу,
максимум 200 попыток на весь явно зафиксированный эксперимент. Сохраняй ошибки,
usage, время, исходные запросы и ответы, не повторяй автоматически. Используй
имеющийся endpoint/model из профиля проекта; ключ только из окружения. Новый
выделенный лимит эксперимента фиксируй явно, старый журнал не удаляй и не обнуляй;
если инфраструктура не позволяет этот лимит, внеси явную настройку с аудитом.
Не копируй личные рабочие базы между машинами ради обхода ограничений.

Запрос: общая тема на русском, конкретные события/сведения, различия дат,
прогнозов и фактов, противоречия, ссылки на предоставленные unit_id/document_id.
Передавай исходники, а не только центроид/заголовок. Ответ не обязан сводить группу
к одному факту. Проверяй существование ссылок. Если полный контекст не помещается,
пометь группу как необработанную; не исключай неудобные материалы молча.
Форматную корректность отделяй от проверки смысловой поддержки.

API-сбой или отсутствие ключа не блокирует локальные эмбеддинги/кластеризацию.
Не заявляй успешное обобщение, если этот этап не выполнен.

## Что вернуть владельцу

- Коммит с кодом выборки/измерений и исправлениями, без корпуса, ключей и результатов.
- Локальный архив результатов: selection, plan, векторы, документы, группы обоих
  вариантов, соседи, manifest с хэшами, параметры, замеры, ручная оценка и API-аудит.
- REPORT.md с числами, типичными удачами/ошибками, ограничениями и рекомендацией
  параметров; никакого заявления о production-готовности без подтверждения.
- Несколько полных примеров «исходники → группа → обобщение», включая неудачные.
- Данные для будущей интерактивной визуализации: все vectors.jsonl + units.jsonl +
  documents.jsonl, membership обоих вариантов и neighbors. Не выдавай расстояния
  будущей 2D-проекции за истинные расстояния исходного пространства.

Интерактивный интерфейс — следующий этап; текущая задача заканчивается большим
воспроизводимым экспериментом и пригодными для него диагностическими артефактами.
